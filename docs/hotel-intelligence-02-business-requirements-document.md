# Business Requirements Document: Multimodal Hotel Intelligence Assistant (prototype)

> **Status:** v1.0, approved by the Product Owner, 23 Nov 2026 (D7). Changes after approval go through the change control log (10).
> Sources: product brief (01), dataset fact sheet (`docs/dataset.md`), the project brief.
> AI quality targets are set in the evaluation plan (07) **before** testing, then copied here in v1.1, so the two always match.

## 1. Product objective

Let a hotel manager search guest reviews and their photos together, in plain English, and get the relevant images, the reviews behind them and a short answer built only from that evidence.

## 2. Prototype scope

- About **500 images** and their reviews from ViMACSA: **501 images, 267 reviews** (selected 23 Nov).
- English translations of the reviews and a description of each image, **tagged as generated**.
- Image and text embeddings (CLIP and SigLIP) in a vector database (Chroma), on this computer.
- Natural-language search; multimodal RAG answers with Claude.
- An evaluation of 20–30 test questions plus a fresh set; a comparison of approaches; a failure analysis.
- A simple app (Streamlit) on this computer.

## 3. User / persona

**Quality / operations manager** at a hotel group, preparing a monthly review of guest feedback. Not technical. Needs evidence they can trust and show to others: the photo, the guest's words, and a summary that doesn't overstate.

## 4. User journey

1. Types a question: *"Show room images associated with negative feedback."*
2. Sees the most relevant images, each with its **similarity score**, its **review** (English, with the Vietnamese original on request) and its **labels** (topic and sentiment, from the source).
3. Reads a **short answer** underneath: *"Guests mainly complain about…"*, each point citing the images and reviews it came from.
4. Clicks an image to see more like it, and the reviews attached to those.
5. Uses the evidence in their monthly report.

## 5. Functional requirements

| ID | Requirement | Brief step |
|---|---|---|
| **FR-01 Selected dataset** | About 500 images and their reviews, selected by a repeatable rule; every image linked to its review | 1 |
| **FR-02 Source and generated fields** | Every field tagged **from the source**, **generated by AI** or **calculated**; nothing generated is presented as source | 1 |
| **FR-03 English reviews** | Each review translated into English, the Vietnamese original kept beside it | 1 |
| **FR-04 Image description** | Each image gets a short description and a scene type (room, bathroom, pool, restaurant, food, lobby, exterior, facility, other), stored with the image and its review | 2 |
| **FR-05 Image embeddings** | Each image embedded with CLIP and with SigLIP | 3 |
| **FR-06 Text embeddings** | Each description and review embedded in the same spaces | 3 |
| **FR-07 Vector database** | All embeddings stored with links to the image, description, review and metadata (labels, scene type) | 4 |
| **FR-08 Text search** | An English question returns the top results (images, with their reviews) and a similarity score for each | 5 |
| **FR-09 Labels in search** | Where a question asks for a topic or a sentiment ("negative", "food"), the source's labels are used, and the app shows how | 5 |
| **FR-10 Search by image** | From any result, find similar images and their reviews (image to text) | 5, learning outcome |
| **FR-11 Grounded answer** | Claude writes a short answer using **only** the retrieved images and reviews, citing which ones support each point | 6 |
| **FR-12 Not enough evidence** | If the evidence doesn't answer the question, the answer says so instead of guessing | 6 |
| **FR-13 App** | Search box, image gallery, review text, similarity score, AI answer | 10 |
| **FR-14 Call log** | Every model call logged: task, **model asked for and model used**, effort, prompt version, tokens, time, cost, status | Monitoring |
| **FR-15 Search log** | Every search logged: question, approach, results, scores, time | 7 |
| **FR-16 Evaluation** | 20–30 test questions with relevance judged by Tez; Precision at 5 and 10, retrieval accuracy, response time, incorrect retrievals; plus a fresh set kept back until the end | 7 |
| **FR-17 Comparison** | Caption search, CLIP search and SigLIP search on the same questions, in the brief's table | 8 |
| **FR-18 Failure analysis** | The worst searches, each tagged with the brief's five causes, with a possible improvement | 9 |

## 6. AI quality requirements

| Area | Requirement | Target |
|---|---|---|
| **Retrieval quality** | Relevant results at the top, judged on the image itself | Precision at 5, set in 07 before testing |
| **First-result accuracy** | A relevant result comes first | Set in 07 before testing |
| **Grounded answers** | No claim in an answer goes beyond the retrieved evidence | **None** beyond the evidence, checked on every test answer |
| **Honest gaps** | When the evidence is thin, the answer says so | Checked on test questions with little evidence |
| **Faithful translation** | Translations keep the meaning and tone | Spot-check; **done** for 9 reviews |
| **Descriptions** | Descriptions describe the scene, not people's appearance or identity | **None** about individuals, checked on a sample |
| **Generated fields tagged** | Every generated field visible as generated in the data and the app | 100% |

## 7. Non-functional requirements

| Area | Requirement |
|---|---|
| **Cost** | Whole project under **$10** of Claude usage. A question with an answer: target under **$0.05** |
| **Speed** | Search under **2 seconds** on this computer; search plus answer under **15 seconds** |
| **Disk** | Fits in the space left (6.4 GB free at the start of Phase 1); installs and downloads shown with their size first |
| **Privacy** | Nothing generated about individuals; reviews and images sent to Claude only with approval |
| **Reproducible** | Selection and evaluation repeatable from the scripts, with fixed seeds and recorded versions |
| **Runs locally** | App and database on this computer; only calls to Claude leave it |

## 8. Data sourcing and ethics

- **Source:** ViMACSA, research use only. Images and reviews are **not published**; GitHub gets code, results and documents. The paper is cited.
- **Translation and descriptions** are generated and tagged; the Vietnamese original is always kept.
- **People in photos:** the system describes scenes, never people's appearance, age, gender or identity.
- **Online processing:** reviews (approved, Decision B) and images (Decision C, Phase 2) are sent to Anthropic only with the Product Owner's yes.

## 9. Out of scope (prototype)

- The full dataset (4,876 reviews, 9,058 linked images).
- Training or fine-tuning any model.
- Hotel names, dates, star ratings or locations as filters: not in the dataset.
- Real hotel data, sign-in, hosting.
- Questions in languages other than English.

## 11. Expected business outcomes

- Managers find the evidence behind feedback in seconds, not hours.
- Decisions about rooms, food and facilities cite what guests said **and** showed.
- The image–review mismatch is visible, so nobody shows the wrong photo for a complaint.
